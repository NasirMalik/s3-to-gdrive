Overview

TES returns PDT in one of two display formats, configured per platform via YAML files:

  • Single Value (DISPLAY_FORMAT_MINUTE_VALUE) — a single number in minutes

  • Range (DISPLAY_FORMAT_MINUTE_RANGE) — a lower and upper bound in minutes

The configs also define which delivery options (Standard, Priority, Saver) have range bounds configured. If a delivery option has no range entry in the config, TES returns null for those fields.

Note: these are TES-side configurations (what TES returns in the API response). Platforms may apply additional local logic. See Use cases where platform PDT does not come from TES for known exceptions.

Why some fields are NULL in logs

  • NULL range fields (std_low, std_high, etc.) for a delivery mode with DISPLAY_FORMAT_MINUTE_VALUE: expected — range fields are not populated when the display format is single value (e.g. Pandora/PeYa/Efood/Talabat pickup).

  • NULL Priority or Saver fields: expected for platforms where that delivery option is not configured (e.g. HungerStation, some PeYa countries have no Priority; Talabat/Efood/Woowa have no Saver).

Key Rules

  • Priority and Saver require an explicit range config. If no range entry exists for that delivery option, TES returns null for those fields in responses and logs. See PDT configs for Priority and Saver delivery options.

  • Display format conditions are per delivery_mode. A platform can have SV for pickup and Range for delivery (Pandora, PeYa, Efood, Talabat), or Range for all modes with no condition (HungerStation, Glovo, Woowa).

  • Configs are defined at country level (with a default per platform). Country-level overrides inherit from the platform default.
